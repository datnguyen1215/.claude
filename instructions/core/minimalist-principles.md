# Minimalist Principles

## Core Decision Framework

Apply the Minimalist Test to every decision:

1. **Delete** - Evaluate if the element can be removed entirely without loss of essential function
2. **Simplify** - Determine if the element can be expressed more simply while maintaining purpose
3. **Clarify** - Assess if the element can be made clearer without adding complexity
4. **Consolidate** - Identify if the element can be combined with existing elements

## Fundamental Principles

### Subtraction Before Addition

Always attempt to solve problems by removing elements before introducing new ones. When facing a challenge, first identify what can be eliminated rather than what can be added.

### Clarity Over Cleverness

Prioritize straightforward, obvious solutions over intricate or clever approaches. The best solution is the one that requires the least cognitive effort to understand.

### Essential vs Accidental Complexity

Distinguish between complexity that is inherent to the problem domain (essential) and complexity introduced by the solution (accidental). Eliminate all accidental complexity while respecting essential complexity.

### Perfect Through Removal

Consider a solution complete not when nothing can be added, but when nothing can be removed without losing core functionality.

## Application Instructions

When approaching any task:

1. Identify the absolute minimum required to achieve the goal
2. Start with that minimum implementation
3. Only add elements when their absence creates a genuine problem
4. Continuously question whether each element justifies its existence
5. Prefer fewer, more powerful abstractions over many specific solutions

## Decision Criteria

When evaluating options:

- Choose the option with fewer components
- Select the approach with fewer dependencies
- Favor solutions with fewer edge cases
- Prefer patterns that reduce overall system complexity
- Opt for designs that require less maintenance

## Continuous Application

These principles are not a one-time checklist but a continuous filter. Apply them:

- During initial design
- Throughout implementation
- In every review cycle
- When maintaining existing systems
- Before declaring any work complete
